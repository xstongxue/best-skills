# 05–09 各篇模板

这五篇让新人动手：跑起来、加功能、查问题、写得像样。

写作要求见 SKILL.md 的 Phase 3，下面不再重复。这五篇另有两点：

- **命令和示例尽量实际跑一遍**，跑不了的标 `⚠️ 未验证`
- 受项目类型影响最大，写之前务必看 [project-types.md](project-types.md)

---

## 05 运行时

**要解决的问题**：让读者能在脑子里把程序跑起来，知道各部分在什么时候、什么环境下执行。

**可以跳过**：单线程、没有并发、不常驻。前端项目**换成**讲页面怎么渲染、状态怎么变。

**素材**：`.project-map.md` 第 6 节 + 线程或协程在哪创建的。

```markdown
> 这篇回答：程序跑起来有哪些线程？各干什么？回调是在哪个线程里执行的？

## 1. 有哪些线程
ASCII 图或 Mermaid flowchart：所有线程、协程、事件循环，各自负责什么。

## 2. 每条线程细说
- 名字、在哪创建的（`path:line`）、什么时候创建
- 循环里做什么
- 哪些回调和函数是在这条线程里跑的 —— 这是新人最需要知道的

## 3. 线程之间要注意什么
- 哪些数据会被多条线程同时碰（要加锁或用原子操作）
- 哪些事不能在回调里做（耗时操作、同步等待、重入调用）
- 死锁和竞态的典型场景，最好是项目里真踩过的

## 4. 启动时都发生了什么
调用链 + 每步做了什么 + 为什么顺序不能换

## 5. 速查
| 问题 | 答案 |
|---|---|
| onMessage 在哪个线程执行？ | 接收线程，别在里面做耗时操作 |
```

**Web 后端改成**：一个请求从进来到返回经过什么、连接池、协程和线程池怎么配、中间件按什么顺序执行。

**Web 前端改成**：什么时候渲染、状态改了为什么会重新渲染、副作用什么时候执行、异步取数据的竞态。

## 06 构建

**要解决的问题**：能看懂、能改、能给新模块加配置。

**素材**：`.project-map.md` 第 1、8 节。

```markdown
> 这篇基于项目实际的构建文件讲，目标是能自己给新模块写构建配置。

## 0. 这套构建工具是什么，为什么用它

## 1. 语法速查
只讲项目里实际用到的：变量、规则、函数、条件

## 2. 逐个文件加注释
项目里每个构建文件，逐行说明什么意思、有什么影响

## 3. 几种产物的区别
库 / 可执行文件 / 容器镜像 / 前端 bundle —— 对比表

## 4. 新模块配置模板
可以直接复制，标出哪里要改

## 5. 常用命令
| 命令 | 干什么 | 状态 |
|---|---|---|
每条都标 ✅ 跑通了 / ⚠️ 没试过

## 6. 常见报错怎么修
| 报错 | 原因 | 怎么修 |

## 7. 调用关系总图
```

**其他类型**：Web 后端讲依赖管理和镜像构建；前端讲打包流程和产物分析；库讲打包发布；数据脚本讲怎么复现环境（锁版本）。

## 07 对接

**要解决的问题**：从零开始接一个新功能进去。

**素材**：`.project-map.md` 第 3、5 节 + 第 04 篇末尾那个文件列表。

```markdown
> 这篇由浅入深，带你从概念到代码，完整接入一个新功能。

## 第一步：先搞清最简单的接入方式
Mermaid 图：3 个核心概念和它们的关系。先讲清概念再动代码。

## 第二步：配置（如果有路由、注册、订阅这类配置）
文件格式、规则、示例

## 第三步：定义接口和数据通道
声明和实现，带详细注释

## 第四步：把主体实现出来
代码模板 + 注释

## 第五步及以后：其他通信方式
异步 / 同步 / 流式 / 二进制等

## 完整例子：加一个业务模块
先规划 → 配置 → 接口 → 服务端 → 客户端 → 构建配置
**这个例子应该真能跑通。** 跑不通就说明哪一步没验证。

## 出问题查哪
| 现象 | 查什么 |

## 加完自己核对
[ ] 每一步都有对应的检查项
```

**关键**：这篇的价值全在"能照着做出来"。写完自己按步骤走一遍，缺的步骤补上——新人在第三步卡住就不会看第四步了。

## 08 调试

**要解决的问题**：出问题能自己搞定。**任何项目都不能跳过这篇。**

```markdown
> 这篇解决三种情况：跑不起来、行为不对、不知道从哪看。

## 1. 日志
- 怎么加（真实示例代码）
- 级别怎么选（表格）
- 一条日志长什么样（逐字段说明）
- 日志不出来怎么办（一条条排查）

## 2. 项目自带的诊断手段
有哪些诊断命令、接口、调试开关，
给一份输出示例，说明怎么看

## 3. 编译阶段
- 怎么让它输出详细信息
- 常见编译报错速查

## 4. 运行阶段
- 常见的崩溃和异常，怎么定位
- 常见的功能不对，怎么一步步查
- 从现象倒查：看到 X 就先查 Y

## 5. 速查
| 问题 | 怎么办 |
```

**关键**：按"现象"来组织，不要按"工具"组织。新人手里只有现象，还不知道有哪些工具。

## 09 设计规范

**要解决的问题**：写出质量更高的代码，做设计决定时有依据。

```markdown
> 这篇回答：接口、模块、数据格式，在这个项目里该怎么设计。

## 1. 什么时候用 A，什么时候用 B
Mermaid flowchart 决策树：不同情况选不同方案

## 2. 命名
- 各类东西怎么起名（表格）
- 好例子和坏例子对比，坏例子最好从项目历史代码里找

## 3. 什么时候该拆开
- 什么时候拆，什么时候别拆
- 判断依据，比如"能不能一句话说清这个模块干什么"

## 4. 数据格式
字段怎么起名、版本兼容、解析时怎么防御

## 5. 常见的错误做法
| 错误做法 | 问题在哪 | 应该怎么做 |

## 6. 完整例子
从一个需求出发走完整个设计过程，展示怎么权衡，不是只给结论
```

**关键**：规范要能在项目现有代码里找到依据。凭通用最佳实践编出来的规范，和项目实际风格冲突时会让新人不知道听谁的——以项目现状为准；如果现状确实不好，写"老代码是 X，新代码建议 Y"。
