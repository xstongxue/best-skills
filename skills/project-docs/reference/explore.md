# 怎么读项目，读完记成什么样

记录文件：`docs/.project-map.md`（点号开头，不和给读者看的文档混在一起）。

后面 8 篇文档里的每个类名、每条路径、每段代码都从这里取。不记下来，写的时候只能靠印象转述，结果就是路径写错、类名拼错、代码编造。

---

## 分三步读，不要一次读完所有源文件

中大型项目读不完，硬来只会把上下文填满噪声。

### 第 1 步：看轮廓（必做）

- 目录树，2–3 层深，**排除** `node_modules` / `build` / `dist` / `target` / `vendor` / `.git` / `__pycache__`
- 构建和依赖文件：`package.json` / `CMakeLists.txt` / `Makefile` / `pom.xml` / `build.gradle` / `go.mod` / `pyproject.toml` / `Cargo.toml`
- `README` / `CONTRIBUTING` / 已有的 `docs/`
- 得出：主要语言、框架、属于哪类项目（对照 [project-types.md](project-types.md)）

### 第 2 步：看骨架

- **入口文件读全文**：`main` / `index` / `app` / `bootstrap` / `cmd/*` / `wsgi` / `Application`
- **接口和类型定义**：`*.h` / `*.d.ts` / `interface` / `abstract class` / `*.proto` / schema / model
- 配置文件、路由表或注册表
- 每个顶层目录或包，一句话说明它干什么

### 第 3 步：跟一个完整例子走一遍（最关键）

挑一个有代表性的示例或功能，优先从 `example/` `demo/` `samples/` 里选——这些是作者自己写的教学入口，最容易看懂。从入口一直追到结束。

这一遍直接成为第 04 篇代码导读的主线，第 07 篇对接指南也要参照它。

**做完这步就开始写。** 缺的细节等写到具体某篇时再去读——需要时精读永远好过提前泛读。

### 项目很大怎么办

超过 500 个源文件时，按顶层模块分批读，每批记一部分，最后合起来。不要指望一次装下整个仓库。

## 更新文档时怎么用这个文件

1. 看「对应提交」那一栏
2. `git diff --stat <那个提交>..HEAD` 拿到改动的文件
3. 按下表找出该重写哪几篇：

| 改了什么 | 要重写 |
|---|---|
| 增删了顶层模块 | 01 架构，可能还有 02 思想 |
| 入口文件或那条主流程 | 04 代码导读 |
| 并发方式、生命周期 | 05 运行时 |
| 构建文件 | 06 构建 |
| 对外接口、扩展点 | 07 对接、09 规范 |
| 日志、诊断工具 | 08 调试 |

4. 重写完把「对应提交」更新成现在的
