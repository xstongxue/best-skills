# 目录页模板和自查清单

## docs/README.md 模板

9 个文件摆在目录里，新人不知道从哪读、能不能跳着读。这一页解决这个问题。

```markdown
# 项目文档

> 面向刚接触本项目的同学，按编号从前往后读。

## 你想干什么，就读哪几篇

| 目的 | 读这些 | 大概要多久 |
|---|---|---|
| 只想大致了解这个项目 | 01 → 02 | 30 分钟 |
| 要修一个 bug | 01 → 03 → 04 → 08 | 半天 |
| 要加一个新功能 | 01 → 03 → 04 → 07 → 09 | 一天 |
| 要改构建或部署 | 01 → 06 | 1 小时 |
| 要全面接手这个项目 | 01 到 09 全读 | 两三天 |

## 篇目

9 行，每行「编号 | 链接 | 一句话」，说明沿用 SKILL.md Phase 2 里的那份。跳过的留空号写原因，形如：

| 篇 | 文件 | 内容 |
|---|---|---|
| 01 | [架构](01_architecture.md) | 项目长什么样 |
| 05 | — | 跳过了：单线程 CLI，没有并发 |
| 09 | [设计规范](09_design_conventions.md) | 怎么设计得更好 |

## 说明

- 文档对应的提交：`<short-sha>`，日期 `<YYYY-MM-DD>`
- 标了 `⚠️ 未验证` 的命令和示例还没实际跑过，照做前自己先确认
```

跳过的篇目**在表里留一行并写明原因**，比悄悄消失有用——它告诉读者"这个项目没有并发"，而不是"文档漏了一篇"。

## 每篇写完自查

```
内容对不对（最重要）：
[ ] 每段代码在贴之前都 Read 过对应文件
[ ] 代码引用带 path:line
[ ] 类名、函数名、路径和实际代码逐字一致
[ ] 没有把项目行为说错
[ ] .project-map.md 里「没弄清的部分」涉及的地方没有硬写
[ ] 没验证过的命令和示例都标了 ⚠️

好不好读：
[ ] 开头有 > 引用块说明这篇解决什么问题
[ ] 复杂的关系有 Mermaid 图或表格
[ ] ASCII 图宽度不超过 80 字符
[ ] 抽象概念配了生活里的例子
[ ] 有对比（不用框架 vs 用框架 / 错的 vs 对的）
[ ] 术语第一次出现有解释
[ ] 用词和术语表一致，没有生造名词

对新人友不友好：
[ ] 没假设读者知道项目背景
[ ] 从"是什么"开始，不直接跳到"怎么做"
[ ] 代码注释说的是"为什么"，不是把代码翻译成中文
[ ] 结尾有速查表或检查清单

长度：
[ ] 在 300–600 行之间
[ ] 单个代码块不超过 30 行（超了就裁剪，注明完整代码在哪）
```
