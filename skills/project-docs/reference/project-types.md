# 不同类型的项目该写哪几篇

9 篇的默认模板偏向 C++ 那类"要编译、有多线程、有进程间通信"的项目。其他类型**必须**按下表替换或跳过，不然会硬套出一堆废话——比如给一个 200 行的 Python 脚本写"线程和进程全景"。

## 怎么判断属于哪类

看仓库根目录有什么文件：

| 有这些文件 | 属于 |
|---|---|
| `CMakeLists.txt` / `Makefile` / `Cargo.toml`，且没有 web 框架 | 系统 / 中间件 |
| `pom.xml` / `go.mod` / `package.json`(express、nest) / `pyproject.toml`(django、fastapi) | Web 后端 |
| `package.json` + react/vue/svelte + `vite.config` / `next.config` | Web 前端 |
| `setup.py` / `pyproject.toml`，只对外提供接口、没有服务入口 | 库 / SDK |
| 大量 `*.ipynb`，或纯脚本 + pandas/numpy | 数据 / 脚本 |

**前后端在同一个仓库**：按代码量多的那边算，或者两边各写一套（`docs/frontend/` 和 `docs/backend/`），在 `docs/README.md` 里说明。

**判断不了就问用户**，不要猜——类型判错会让 5 篇文档跑偏。

## 对照表

| 篇 | 系统 / 中间件 | Web 后端 | Web 前端 | 库 / SDK | 数据 / 脚本 |
|---|---|---|---|---|---|
| **01 架构** | 分层 + 动态库依赖 | 分层 + 请求怎么流转 | 分层 + 组件树 | 对外提供哪些接口 | 数据从哪到哪 |
| **04 代码导读** | 跟一个示例 | 跟一个请求 | 跟一次用户操作 | 跟一次接口调用 | 跟一次完整运行 |
| **05 运行时** | 线程和进程 | 一个请求的生命周期、连接池、协程 | **换成**：页面怎么渲染、状态怎么变 | ⚠️ 常常可以跳过 | ⚠️ 跳过，改讲数据量和耗时 |
| **06 构建** | Make/CMake 逐文件讲 | 依赖管理 + 容器镜像 | 打包流程（Vite/Webpack）| 怎么打包发布 | 怎么复现环境（venv / conda / 锁版本）|
| **07 对接** | 加一个模块 / 通道 | 加一个接口 / 服务 | 加一个页面 / 组件 | 扩展点、插件怎么写 | 加一个数据处理步骤 |
| **08 调试** | 崩溃 / core dump / 日志 | 日志 / 链路追踪 / 接口调试 | DevTools / 看状态 / 看网络 | 单测 / 怎么写最小复现 | 数据对不对、中间结果存下来看 |

没列进表的三篇：**02 思想**和 **09 规范**所有类型都照写；**03 语言特性**除数据脚本可精简外照写。

## 哪几篇可以跳过

| 篇 | 什么情况下可以跳 |
|---|---|
| 03 语言特性 | 用的是读者几乎肯定熟悉的语言，而且没有任何特殊用法。**很少见，别轻易跳**——多数项目都有值得单独说的写法 |
| 05 运行时 | 单线程、没有并发、不常驻、生命周期不复杂 |
| 06 构建 | 不用构建（纯脚本，`python x.py` 直接跑）。这时"环境怎么准备"那节仍要保留，可以并到 01 |
| 07 对接 | 项目不提供扩展点，纯应用，没人会二次开发 |
| 01 / 02 / 04 / 08 / 09 | **不能跳。** 任何项目都需要知道结构、设计原因、从哪读代码、怎么查问题、按什么约定写 |

跳了哪篇，都要在 `docs/README.md` 里写明编号和原因。

---

## 编号规则

**编号固定，跳过的留空号。**

跳过 05 时，目录里就是 `01,02,03,04,06,07,08,09`，不要把 06 改名成 05。

原因：

- "03 是语言特性"这种约定要稳定，用户和后续对话才能用编号互相指代
- 以后更新文档靠编号找篇目，挪过之后对不上
- 空号本身就是信息：这个项目没有并发

---

## 有一条顺序不能变

不管什么类型，**03（语言特性）必须在 04（代码导读）前面**。读者没做语言上的准备就进代码导读，会卡在语法上，而不是卡在业务逻辑上——后者才是导读该解决的。
