## 01 框架架构

**目标**：建立全局认知，知道项目"长什么样"。

```markdown
> 本文面向刚接触项目的新同学，从"这是什么"开始，建立完整系统认知。

## 0. 读前须知（背景概念）
解释项目用到的基础概念，读者可能不了解的：
- 这类项目解决什么问题（类比生活场景）
- 关键术语定义（IPC / 中间件 / 动态库 等）
- 为什么用这门语言（而不是更流行的选择）

## 1. 整体分层架构
ASCII 图：每层是什么、依赖关系向下

## 2. 目录结构详解
带注释的树形结构，每个目录/文件一句话说明职责

## 3. 核心库/模块详解（按层）
每个模块：
- 提供什么能力
- 内部关键类及其关系（ASCII 图）
- 使用示例代码（来自真实文件）

## 4. 构建体系
构建文件的层级关系、关键编译选项含义

## 5. 示例工程解析
如果有 demo/example，在这里解读它的整体架构

## 6. 快速定位代码
表格：想了解 X → 去看哪个文件的哪个函数
```

## 03 语言特性

**目标**：读代码前的语言基础准备，只讲项目里真实用到的特性。

```markdown
> 本文只讲本项目代码里出现的语言特性，结合真实代码解释。

## 每个特性（重复以下结构）：
### 特性名
**项目里在哪用**：贴出真实代码片段（文件路径 + 行号）
**解决什么问题**：对比"没有这个特性时怎么写"
**要点**：1-3 条核心规则

## 命名规范速查表
| 类型 | 前缀/规则 | 例子 |
```

**常见需要解释的特性**（根据项目语言选取）：
- C++：纯虚接口、多重继承、std::bind/lambda、override、= delete、初始化列表
- Java/Kotlin：interface、泛型、协程、companion object
- Python：decorator、dataclass、ABC、asyncio
- TypeScript：interface vs type、泛型、装饰器

文件树 + 每个文件的职责说明

## 05 运行时模型

**目标**：脑子里能跑起来程序，知道哪些线程/进程在干什么。

```markdown
> 本文解答：程序跑起来有哪些线程？每条线程干什么？回调在哪个线程触发？

## 1. 线程/进程全景图
ASCII 图：进程内所有线程 + 各自职责

## 2. 每条线程详解
- 名称、创建时机、循环逻辑
- 哪些回调/函数在这条线程里执行

## 3. 线程交互注意事项
- 哪些操作在不同线程里访问同一数据（需要加锁）
- 哪些操作不能在回调线程里做（耗时操作、同步调用）
- 死锁的典型场景

## 4. 启动顺序全流程
代码调用链 + 每步做了什么

## 5. 一句话速查表
| 问题 | 答案 |
```

## 写作质量检查清单

每篇文档写完后过一遍：

```
内容准确性：
[ ] 所有代码片段来自项目真实文件（不是编造的）
[ ] 类名、函数名、文件路径与实际代码一致
[ ] 没有对项目行为的错误描述

可读性：
[ ] 顶部有 > 引用块说明本篇目标
[ ] 有 ASCII 图或表格辅助理解复杂关系
[ ] 抽象概念有生活类比
[ ] 有对比（没有框架 vs 有框架 / 错误 vs 正确）
[ ] 专业术语首次出现时有解释

对新人友好：
[ ] 不假设读者知道项目背景
[ ] 从"是什么"开始，不直接跳到"怎么做"
[ ] 代码注释解释"为什么"而不只是"是什么"
[ ] 结尾有速查表或检查清单

整体顺序：
[ ] 03（语言特性）在 04（代码导读）之前
[ ] 每篇文档建立在前几篇的基础上，不跳跃
[ ] 新人按 01→09 顺序读完，不会卡住
```
