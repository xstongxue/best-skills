# 发明内容写法

## 适用场景

- 用户要写发明内容
- 用户已经有背景技术和权利要求，需要补发明目的、技术方案和有益效果

## 输入要求

- 背景技术中的缺陷列表
- 权利要求全文（独立权利要求 + 从属权利要求）
- 预期技术效果

## 写作目标

发明内容 = 技术方案展开 + 原理说明 + 有益效果。

**技术方案部分**：以权利要求语言为基础，在每个技术特征描述之后补充该特征的技术原理说明——不能与权利要求书完全一样，也不能只是功能摘要。

**有益效果部分**：从技术原理出发推导效果，不写"提高了准确率"这类结果口号，要说清楚"为什么这样设计会有这样的效果"。

## 推荐结构

### 第1段：发明目的

- 格式："针对现有…技术不足，本发明目的在于提供一种…，通过…，实现…。"
- 对应背景缺陷，点出核心技术路径

### 第2段：引出技术方案 + 核心方法步骤

- 固定句式："本发明通过以下技术方案实现上述目的："
- 然后列出独立权利要求1的全部步骤（方法类用"包括：\n步骤1；\n步骤2；……"格式）
- **在步骤列表之后**，紧接一段技术原理补充说明：
  - 针对哪个技术问题（对应背景缺陷）
  - 通过什么机制解决（设计思路）
  - 带来什么可量化或可描述的改善（技术效果）

### 第3～N段："进一步地，……"

每个关键从属权利要求对应一个"进一步地"段落，**每段分为两部分**：

**Part A：技术方案描述**
- 以权项语言为基础，去掉"根据权利要求X所述的方法，其特征在于"引导语
- 含公式的权项：公式必须在此处完整写出，格式与权利要求一致（独立成行、"其中，"解释行）
- 技术方案描述与权项的差异仅在于去掉引导语，内容保持一致

**Part B：技术原理补充说明**（段落结尾另起一句或换行）
- **该特征针对的技术问题**：指向背景技术中某个具体缺陷
- **设计思路**：为什么用这种方式而不是其他方式
- **工作原理**：机制如何运转（可引用公式中的变量关系说明）
- **取得的技术效果**：具体改善了什么、相比原有方案有何优势

Part B 可写成 1-3 句连贯的说明，无需单独分小标题，避免格式过重。

顺序建议：智能体/模块定义 → 执行链路 → 评分模式/公式 → 语法扣分 → 图形识别 → 多智能体融合 → 个性化反馈 → 缓存机制

### 第N+1段：第二/三/四目的（系统、设备、介质）

- 格式："本发明的第二个目的在于提供一种…系统，用于执行上述方法，所述系统包括：[模块列表]。"
- 格式："本发明的第三个目的在于提供一种计算机设备，…，实现上述…方法。"
- 格式："本发明的第四个目的在于提供一种存储介质，…，实现上述…方法。"

### 最后：有益效果

- 格式："本发明的有益效果："
- 用"1. …\n2. …\n"编号列出
- 条目数量与背景缺陷数量一一对应
- **每条效果必须包含：具体技术手段 → 工作原理 → 产生的效果**，三层缺一不可
- 禁止只写效果结果（如"提高了准确率"），必须说明通过什么技术手段、因为什么原理才有该效果

## 有益效果写法要求（重点）

每条有益效果应按以下逻辑展开：

> 本发明通过【具体技术手段，与权项一致】，【该手段的工作机制说明】，从而【对比现有技术的具体改善】。

示例（好的写法）：
> 本发明以题干语义向量、标准答案和评分规则配置三元组的哈希值为缓存索引键，使同一题目的多份作答批改共享同一次评分规则解析结果，将模型调用次数从与作答数量线性相关降低至与题目数量线性相关，在班级批改场景下（通常30至50份作答）大幅降低推理成本，使系统在高并发下仍能保持较低延迟。

示例（不好的写法）：
> 本发明设计了缓存机制，显著降低大型语言模型调用频率，提升系统并发处理能力。

## 语言约束

- "进一步地"Part A 以权利要求语言为基础，不要改写成功能摘要
- "进一步地"Part B 必须包含技术问题、设计思路、工作原理、技术效果，不能只是权项重述
- 有益效果要从技术原理推导，不要只写结果口号
- 不要把发明内容写成比摘要更短的版本
- 系统/设备/介质目的段不能遗漏，否则保护对象不闭环

## 输出模板

针对现有【技术领域】在【缺陷方面】的技术不足，本发明目的在于提供一种【方案名称】，通过【核心路径】，实现【技术目标】。

本发明通过以下技术方案实现上述目的：

一种【方法名称】，包括：
【步骤1（与权项1一致）】；
【步骤2】；
【步骤3】；
【步骤4】。

上述方案针对【对应的背景缺陷】，通过【设计思路】，使【工作机制说明】，实现了【技术效果】。

进一步地，【从属权项2对应内容，含公式（Part A）】。

上述【该特征名称】设计，针对【技术问题】。通过【设计思路】，【工作原理说明】，从而【技术效果（与现有技术对比）】。（Part B）

进一步地，【从属权项3对应内容（Part A）】。

上述【该特征名称】，针对【技术问题】，通过【设计思路和原理】，取得了【技术效果】。（Part B）

……（每个关键权项一段，均含Part A + Part B）

本发明的第二个目的在于提供一种【系统名称】，用于执行上述方法，所述系统包括：【模块列表】。

本发明的第三个目的在于提供一种计算机设备，包括处理器以及用于存储处理器可执行程序的存储器，所述处理器执行存储器存储的程序时，实现上述【方法名称】。

本发明的第四个目的在于提供一种存储介质，存储有程序，所述程序被处理器执行时，实现上述【方法名称】。

本发明的有益效果：

1. 【技术手段】+【工作原理】+【对比现有技术的具体改善】；
2. 【技术手段】+【工作原理】+【对比现有技术的具体改善】；
……

## 常见问题 / 禁忌

- "进一步地"段落与权利要求书内容完全一样，缺少技术原理补充说明
- 技术方案段只写功能描述，不复用权利要求语言
- 缺少"进一步地"展开段，只有总流程4步就跳到有益效果
- 有益效果只写效果结果（"提高了准确率、降低了成本"），不分析技术原理
- 有益效果与技术手段脱节，对不上权项内容
- 忘记系统/设备/介质的目的段，导致保护对象不闭环
- 公式只在具体实施方式出现，发明内容中缺失
