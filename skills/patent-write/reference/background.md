# 背景技术写法

## 适用场景

- 用户要写背景技术
- 用户需要从现有方案缺陷引出发明目的

## 输入要求

- 技术领域与应用场景
- 现有常见做法（具体方法，不是泛泛而谈）
- 现有做法的具体缺陷

## 写作目标

把"为什么要做这个发明"写清楚：通过"行业背景→现有技术是什么→现有技术哪里不够→引出本发明需要解决的问题"自然铺垫出发明的必要性。背景技术中**只描述现有技术及其缺陷**，不引入本发明任何解决方案。

## 推荐结构

### 精简版（推荐，3段）

适用于缺陷条目可自然合并、不需要逐条展开的场景：

**第1段：行业背景 + 核心挑战**
- 写行业趋势或技术场景的重要性，直接点出核心挑战
- 不要一上来就写发明方案，不要只写市场分析
- 可以在同一段内简要列举不同场景下的异构需求（2-3个例子）

**第2段：现有技术方案 + 综合缺陷**
- 明确说现有系统/方法通常采用哪几类方案
- 对每类方案指出其具体局限（不是笼统说"性能不足"）
- 多个缺陷点可合并在同一段内以分号分隔，不强制编号
- 格式参考："现有系统通常采用……然而，这些方法……此外，……"

**第3段：总结引出**
- 一句话总结不足，引出本发明需要解决的问题
- 格式："上述问题表明，现有…方法在…方面均存在明显不足，亟需一种能够…的…方法。"

### 详细版（含编号缺陷列表，适用于缺陷条目多且独立）

在精简版第2段位置，改为：
- 先写"现有系统通常采用…然而…"的铺垫段
- 再用"综上所述，现有…存在如下主要问题：1、…；2、…"的编号列表
- 缺陷条目要与后文有益效果一一对应
- 每条前加标题词，如"评分逻辑难以覆盖："

### 结尾段（两种格式均适用）
- 精简版："上述问题表明，现有…方法在…方面均存在明显不足，亟需一种…的方法。"
- 详细版："因此，需要一种能够…的…方案，以满足实际场景中的需求。"

## 语言约束

- 缺陷要具体，最好对应后文发明内容的技术手段
- 不要写成市场分析，不要写政策堆砌
- **不要在背景技术中出现"本发明通过…""本发明采用…""本发明提出…"等表述**
- 不要出现任何对本发明解决方案的描述，包括方法名称、模块名称、核心机制
- 举例要贴近技术本质，不要举产品功能例子
- 避免把缺陷列表重复铺陈两遍（第2段已描述过的缺陷，编号列表不要再完整重写一遍）

## 输出模板（精简版）

随着【行业趋势】，【技术场景】已成为【重要性描述】。【核心挑战简述】：【异构需求例子1】，【异构需求例子2】，不同场景的处理逻辑高度异构。

针对【本发明所针对的场景】，现有系统通常采用两类方案：一是【方案A及其局限】；二是【方案B及其局限】。此外，【补充局限说明】；【另一缺陷说明】。

上述问题表明，现有【技术领域】方法在【缺陷维度1】、【缺陷维度2】、【缺陷维度3】方面均存在明显不足，亟需一种能够【方向描述】的【技术领域】方法。

## 输出模板（详细版）

随着【行业趋势】，【技术场景】已成为【重要性描述】。在众多应用场景中，【核心挑战】因【原因】格外受到关注。

当前，【技术场景】已在【已成熟的部分】广泛应用，效果相对稳定。然而，针对【本发明所针对的场景】，现有系统通常采用以下方案：一是【方案A及其局限】；二是【方案B及其局限】。此外，【补充局限说明】。

综上所述，现有【技术领域】方法存在如下主要问题：
1、【缺陷标题】：【缺陷描述】；
2、【缺陷标题】：【缺陷描述】；
3、【缺陷标题】：【缺陷描述】；
4、【缺陷标题】：【缺陷描述】。

因此，需要一种能够【方向描述】的【技术领域】方案，以满足实际场景中的需求。

## 常见问题 / 禁忌

- 只写政策、趋势，不写现有技术具体做什么
- 缺陷和后文技术方案、有益效果对不上
- **将本发明的技术方案写入背景技术**（出现"本发明通过…""本发明采用…"等表述）
- 直接跳到编号缺陷列表，缺少现有技术铺垫段
- 详细版中缺陷列表与前文铺垫段重复，内容二次罗列
- 结尾引出句描述了本发明具体实现路径（如"需要一种基于多智能体协同的…"并展开说明方案）
